# Godzivo — загрузка на GitHub

## 1. Сначала сохрани свои данные

На старом адресе Godzivo открой **Настройки → Скачать резервную копию**. Сохрани JSON отдельно; в публичный репозиторий его не загружай.

## 2. Создай репозиторий

1. Открой https://github.com/new.
2. Repository name: **Godzivo**.
3. Для бесплатной публикации через GitHub Pages выбери **Public**.
4. Отметь **Add a README file**, чтобы сразу появилась ветка `main`.
5. Нажми **Create repository**.

## 3. Загрузи приложение

1. Распакуй архив `Godzivo-v1.0.0-GitHub-Structured.zip`.
2. В репозитории выбери **Add file → Upload files**.
3. Перетащи содержимое распакованного архива. `index.html`, папки `assets`, `docs`, `scripts` и остальные файлы должны лежать в корне репозитория, а не внутри дополнительной папки. ZIP загружать не нужно.
4. Если система скрывает `.gitignore` и `.nojekyll`, включи показ скрытых файлов. Для работы самого приложения они не обязательны.
5. Назови commit: `Godzivo v1.0.0 — initial release` и сохрани изменения в `main`.

Проверь: в корне репозитория виден `index.html`, рядом папка `assets`. При загрузке обновлений сохраняй структуру папок.

## 4. Включи сайт

1. В репозитории открой **Settings → Pages**.
2. В **Build and deployment → Source** выбери **Deploy from a branch**.
3. Укажи ветку **main** и папку **/(root)**.
4. Нажми **Save**.
5. Дождись публикации. Статус виден в **Actions**, ссылка — в **Settings → Pages**.

Ожидаемый вид адреса: `https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/Godzivo/`. Фактическую ссылку копируй из Pages.

## 5. Перенеси записи

На новом сайте открой **Настройки → Восстановить из файла** и выбери ранее скачанный JSON. Записи смен и копилка восстановятся вместе.

На iPhone открой новый адрес в Safari → **Поделиться → На экран «Домой»**. Старую иконку можно удалить после проверки нового приложения и переноса данных.

## 6. Как будем выпускать обновления

Присылай ссылку на репозиторий и нужные изменения. До отдельного разрешения я могу читать исходники и готовить ZIP с обновлением. Загружай изменённые файлы через **Add file → Upload files** в те же пути, сохраняя названия. После commit в `main` сайт обновляется автоматически; проверь результат в Actions.

Перед крупным обновлением скачай JSON-копию. Для фиксации версии: **Releases → Draft a new release**, создай тег `v1.0.0` и опубликуй описание. Следующие выпуски — `v1.0.1`, `v1.1.0` и так далее.

Приложение на GitHub Pages будет доступно посетителям по ссылке. Их записи хранятся в их собственных браузерах и не смешиваются с твоими.
